THE ANDROID CONNECTION

Your computer prepares.
Your phone connects to the carrier.

The Python CLI and Android app are separate software. SMS Gateway for Android is an external project, not an app distributed by this repository.

API acceptance → queueing → device processing → carrier delivery are separate stages. A successful API response is not a delivery receipt. This CLI does not poll delivery receipts.

What you need for real submission

  • A compatible Android smartphone with the official gateway app and appropriate SMS permissions.
  • A suitable SIM, active mobile service, device availability and connectivity for the selected mode.
  • Provider and carrier authorization, with their charges and restrictions reviewed.
  • A separate computer or controlled runtime for Python. This is not an iOS gateway.
Official Android app installation guide ↗

Set up the external app

  1. Follow the official installation and permissions guidance for your device.
  2. Choose a gateway mode below and configure it in the Android app.
  3. Keep gateway credentials private and verify the endpoint contract before any authorized operation.

Installing this repository does not install the phone app. No APK is hosted here.

Public Cloud Server · provider-routed

The CLI calls the provider’s cloud API, which routes queued messages to the registered Android device. The device needs internet connectivity. Phone numbers and message content pass through third-party infrastructure; assess its privacy terms. This client does not implement the provider’s optional end-to-end encryption.

The default endpoint is https://api.sms-gate.app/3rdparty/v1/messages. The existing client uses Basic authentication; the provider now recommends JWT for new integrations while retaining Basic compatibility.

Official cloud setup
Local Server · controlled network

The Python client communicates with the Android device over your controlled network. The official local example uses HTTP, but this CLI refuses plain HTTP for live endpoints. A trusted HTTPS proxy or equivalent TLS deployment is required; do not disable certificate checks. Configure the full compatible URL using SMS_API_ENDPOINT and verify the deployed route/version.

Local mode supports Basic authentication. Network access, device service availability and secure routing are operator responsibilities.

QUICK START · NO SMS

Start with a completely offline Dry Run.

Install Python 3.10–3.14 and Git on your computer. Package access is needed during installation; the default first run does not contact a gateway. No Android phone, credentials or .env file is needed for this example.

Windows · PowerShell

Run from a new terminal. The Python launcher selects your installed supported version.

git clone https://github.com/AlirezaBelal/batch-sms-campaign-automation.git
cd batch-sms-campaign-automation
py -3 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
python main.py

If local policy prevents activation, run .\.venv\Scripts\python.exe -m pip install -r requirements.txt, then .\.venv\Scripts\python.exe main.py.

macOS · Terminal

Use an installed Python 3.10–3.14.

Docker · network-disabled Dry Run

Run in a POSIX shell from the repository root. The existing image runs as a non-root user; the example needs no secrets.

docker build -t batch-sms-campaign-automation .
docker run --rm --network none \
  -e SMS_DRY_RUN=true -e SMS_SEND_ENABLED=false \
  -e SMS_CSV_FILE_PATH=/tmp/contacts.csv \
  -v "$PWD/examples/contacts.example.csv:/tmp/contacts.csv:ro" \
  batch-sms-campaign-automation

Docker build needs package access. Durable private state and separately authorized setup are required for any later live container use.

Full installation and troubleshooting guidance ↗

Authorization is a deliberate operator step.

No schedules, automatic sends or blind retries. Development and website demonstrations never transmit SMS.

Advanced · prepare an explicitly authorized live operation
  1. Install and configure the official Android gateway app and selected mode; verify device, carrier and provider requirements.
  2. Privately review the actual consent evidence, recipients and message purpose. Never use the bundled example for real submission.
  3. Maintain a suppression CSV with the phone header and configure SMS_EXCLUSIONS_FILE. There is no automatic inbound STOP handler.
  4. Optionally copy .env.example to a private .env. Configure SMS_USERNAME, SMS_PASSWORD and a trusted HTTPS endpoint. Keep secrets out of source control.
  5. Set the actual CSV path, reviewed non-demo SMS_CONSENT_SCOPE, conservative recipient/rate bounds and positive SMS_ESTIMATED_UNIT_COST / SMS_MAX_ESTIMATED_COST.
  6. Review third-party processing, carrier terms and applicable requirements. No compliance certification is claimed.
  7. Run python main.py and review its Dry Run preflight first.
  8. Only after separate deliberate authorization, the established controls require SMS_DRY_RUN=false, SMS_SEND_ENABLED=true, valid credentials, and --live with matching --campaign-id and --confirm-campaign values. This is not a copy-and-run sending example.
  9. Reconcile unknown or rejected outcomes with the provider. Preserve the journal and stable ID; never delete state or change IDs to force retransmission.

The opt-out snapshot is checked before each request; a small check-to-send race remains. Interrupt a campaign if a withdrawal becomes known. SMS charges may occur; cost caps bound an estimate, not actual billing.
